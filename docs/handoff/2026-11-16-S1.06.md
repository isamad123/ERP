# Handoff: S1.06 access control (roles, permissions, data scopes, field security, maker-checker)

- **Done:**
  - One engine decides permissions, data scopes and field access for every endpoint: `Erp.Kernel.Infrastructure/Access/AccessEngine.cs`.
    It reads the user's roles (own and group assignments valid on the injected clock's date) fresh in one batched query per
    request (ruling D). Placeholders `NoGrantsPermissionChecker` and `DataScopesNotConfigured` are gone.
  - Data scopes use the new data-design key `scope:` (CR-018, CR-023). Team, department and below come from the HR module
    through `Erp.Kernel.Contracts.Access.IWorkforceDirectory`, implemented in `Erp.Hrm.Infrastructure/Access`; the kernel
    never reads HR tables. Subtree = the org units of the user's current assignments and everything below them in
    reporting hierarchies (`org.org_unit_links`, cycle-safe query).
  - Field security comes from `field_class:` (salary list, ruling B), from field rules per role, resource and field
    (`class:salary` and resource `*` supported) and from custom fields (`custom.<key>`). Generated reads leave hidden
    fields out and mask masked ones (`****` + last 4). Generated writes refuse changes to non-editable fields with 400
    `errors.access.field_not_editable`; a missing value keeps the stored one.
  - Writes are checked against the data scope before and after the change (403 `errors.access.out_of_scope`).
  - Registry and baseline roles come from module access manifests (`*/Access/permissions.g.json`, generated, and
    `baseline-roles.json`). They are applied by provisioning and `migrate` (`AccessSetup`, idempotent; roles the customer
    edited are left alone, Q8; codes no longer declared are retired).
  - Roles, assignments, groups, maker-checker and previews: `AccessAdministrationService*.cs`, endpoints
    `Erp.Kernel.Api/Access/AccessEndpoints.cs`.
  - Last-tenant-admin guard: `TenantAdminGuard`, also used by `UserAdministrationService.ChangeStatusAsync`.
  - Role layer of the identity policy: privileged users need MFA and 14-character passwords; `iam.mfa.required` can be
    set per role.
- **Tables and migration:**
