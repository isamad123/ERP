# Handoff: S1.04 tenant-isolation test suite

- Done: `tests/Erp.IntegrationTests/Tenancy/Isolation/`. The suite reads every endpoint from the API host's own endpoint
  metadata (`EndpointInventory`, 671 customer endpoints + `/health` today) and runs `CrossTenantProbe` on each as one
  xUnit theory row: B's host and token with A's ids in path, list filters and body (with and without headers/query naming
  A) → 404 or no A data; crossed host/token, no token, forged token → 401 (CR-008); unknown host → 404; no 5xx; A's
  database fingerprint (count + MD5 of every row of every table) unchanged; positive controls (A reads, lists, updates,
  deletes its own row; B lists its own row) so no pass is vacuous. Database level: every login of each customer is refused
  by the other customer's database and by the control-plane database (S1.03 already revokes public connect there).
- Self-test: `..._the_suite_catches_an_endpoint_that_reads_without_the_customer_connection` maps a deliberately broken
  endpoint (keeps the first customer's data source) and proves the probe reports the 200 and the leak.
- CI: job `tenant-isolation` (trait `Suite=TenantIsolation`); the main integration step excludes that trait. Making it a
  required check is a GitHub branch-protection setting (product owner).
- For every later slice that adds endpoints: nothing to register. The endpoint must (1) require authorization, (2) carry
  `GeneratedEndpointMetadata` naming the table it serves, and (3) have a list/get/create/update/delete route shape. Anything
  else fails `..._every_endpoint_of_the_running_host_is_covered_by_the_suite` and the probe: extend `CrossTenantProbe`
  (new `EndpointKind`) in that slice rather than exempting it. `EndpointInventory.TenantFree` exemptions need the product
  owner's approval.
- For S1.06: the suite replaces the permission checker and data scopes with allow-all test doubles so calls reach the data.
  Keep that override when the real services arrive, otherwise every call is a trivial 403.
- `RowFactory` gained optional `firstValue`, `companyId` and `enumChoice` parameters (defaults keep the S1.02 behaviour).
- Run time: about 5.5 minutes locally (fingerprint of the whole customer database twice per endpoint).
