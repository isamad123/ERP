## Built
The 30-day rule now pays the days employed (amount / 30 x min(30, days employed), a whole month in full; custom divisors the same), engine version `S1.35b.1`. Calculate locks first, then queues the job `hrm.payroll_calculate` in lanes; each lane calculates its employees in chunks, each chunk saving results, lines, a trace per result and the checkpoint together, so a killed worker's lanes continue on another worker. Cancel stops at the next chunk; progress and the reasons of incomplete employees are in the run summary. Recalculation of some or all employees replaces unlocked results as new row versions (the change log keeps the history). The trace (inputs, versions, every step, rounding, engine version, result hash) is read with `hrm.pay.trace.read` and the salary class, never audited. 10,000 employees: 39 s in the build container.
