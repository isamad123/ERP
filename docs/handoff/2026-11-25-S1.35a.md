## Built
A payroll officer creates the regular run of a pay group and period and calculates it. The calculation first locks the period's attendance and leave (refused while days are not processed or exceptions are open, unless the officer accepts them), then takes each employee's snapshot (employment and days in the group, assignments, compensation, structure, component versions, lookup tables, attendance and leave totals, overtime, lateness, adjustments, one-time inputs, policy versions, each statutory calculator's frozen data), stores it compressed with its SHA-256 and calculates from the stored form: every method in structure order, each component's own pro-rata rule (joiners, leavers, unpaid leave, mid-month changes), one-time inputs, rounding to the currency's minor unit by the company's mode. Statutory components go only to a registered `IStatutoryCalculator`; with none, the employee is incomplete, gets no result and the run does not finish. When every employee has a result the run is `calculated` and `hrm.pay_run.calculated` is published. One-time inputs are entered in bulk (all or none) and become consumed by the run. Once a run is locked the database refuses any change to its employees, results, lines and traces, and the run only moves forward. Amounts are salary-class data everywhere.
