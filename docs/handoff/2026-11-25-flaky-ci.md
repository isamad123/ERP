# Flaky CI tests (R-317, defect fix, no slice)

**Built.** Evidence from 33 failed `ci` runs (23 to 25 Nov): most red runs were real defects of the pull request or clock-dependent tests (fixed by R-286); the rest are below.
- `IdentityCryptoTests.S105_review5`: the test hoped one hash was still running when seven more threads asked. It now takes the hasher's only place itself, so every caller is refused, then checks real overlap and release. Before: 7 of 40 runs failed under CPU stress; after: 0 of 20.
- `NumberingAllocatorTests` (gap-allowed, 100 transactions): no 10 s wall-clock; all 100 transactions must be open at once (rendezvous, 120 s deadlock guard only). Per-allocation timing: median of 200 rounds against a plain round trip measured in the same run (limit 15 times).
- Browser axe scans (`e2e/support.ts accessible()`): waits for finite animations and transitions to finish (read from `document.getAnimations()`, not slept). Cause of the colour-contrast findings: primary buttons fade their background and axe measured the blend.
- **Product fix:** scrolling table regions (attendance reports, team month, attendance requests, live people lists, leave day, ledger and request tables) are now `role=region`, named, `tabIndex=0`, with a focus ring. Without a focusable cell a scrolling region cannot be reached by keyboard (WCAG 2.1.1); axe flagged it once the data was wide enough. No identity, hashing or access code changed, so no Opus review.

**Not fixed.** S1.30b 10,000-employee test (2116 ms against 2000 ms once): a real performance requirement; proposal to the coordinator: run it as its own CI step on an idle runner. `JobCentreApiTests.S111a` (nextRunAt null once) and `StrengthReportTests.FR_HRM_POS_04` (Chromium PDF) not reproduced: hypotheses. About 19 `erp-table-scroll` wrappers in admin and HR screens have the same shape as the fixed defect (R-317).

## Writing reliable tests
1. Wait for the populated region (a visible row or heading) before `accessible()`; never scan a loading screen.
2. Give seeded cells, regions and buttons accessible names; a scrolling region needs a name and a keyboard stop.
3. Never assert on a colour while something fades: `accessible()` now waits for animations.
4. No wall-clock thresholds: count operations, use a rendezvous, or compare with a baseline measured in the same run (median).
5. To prove a refusal or cap, hold the resource in the test instead of racing for it.
6. Company dates come from the Asia/Karachi harness clock, never `DateTime.UtcNow` (19:00 UTC is already tomorrow).
7. Browser tests under heavy CPU load time out at 15 to 20 s; check load before blaming a screen.
