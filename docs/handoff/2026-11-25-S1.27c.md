## Built
An Administration screen "API clients" (`/admin/api-clients`) and its server: create a client with permissions (only those flagged for keys), allowed addresses, a calls-a-minute limit and an optional expiry; the key is shown once with a copy button; make a new secret (the old one keeps working for 60 minutes by setting), revoke, and the use of each key by day. A connected system calls with `Authorization: ApiKey <clientId>.<secret>`; the customer comes from the host name only. A key cannot do anything outside its permissions, cannot reach any `/api/iam` path and never opens a web session. Over the limit a call gets 429 with the wait time; one notice per client and day goes to the people who manage API clients; one notice goes out before a key expires. The device push endpoint of S1.27b is the first endpoint a key can call (`hrm.attendance_devices.push`, flagged `apiClient`); its signature stays.

To let another endpoint be called by a key: flag its permission `"apiClient": true` in the module's `permissions.json` and add `.WithMetadata(new ApiClientEndpointMetadata(permission))` to the endpoint (see `DeviceEndpoints.cs`). A permission never flagged cannot be given as a scope; an endpoint without the metadata answers 403 to every key.
Operator: behind a load balancer set `Network:TrustedProxies` (the balancers' addresses or CIDR ranges), otherwise every caller shows the balancer's address and keys are refused by their allow list (R-297). `Api:UsageFlushMilliseconds` (default 60000) sets how often the hosts add their counts to the database.
