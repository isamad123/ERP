## Built
Signed packs: a zip with a manifest (id, kind, version, country, licence key, titles, release notes, compatible product versions, dependencies, merge rule per type, objects with
hashes) and one file per object (each with its source and "verify before go-live"), ECDSA P-256 over the canonical manifest with keys of purpose `pack`. Operator commands `pack build|sign|publish|list`;
the catalogue `cp.pack_catalog` keeps the signed file and re-checks the signature before every install. Installer: one transaction per pack, every object through its module's handler (kernel:
setting and label at the pack layer, option lists and items, holiday calendars and holidays, banks; HR: policies per company of the pack's country), recorded in `cfg.pack_items`; the customer's
changes are found by comparing each object with what the installer left, kept on upgrade and listed as conflicts with both values ("take the pack value"); removed objects are retired, never deleted.
Pack manager `/settings/packs` (installed, contents, compatibility, changed objects, conflicts, newer versions, install), maker-checker `cfg.packs.requires_approval`; `tenant provision --packs`; wizard step `step_packs`.
