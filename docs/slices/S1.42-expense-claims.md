## Goal
Employees claim expenses with receipts; the system warns approvers about anything unusual (over the limit, duplicate or missing receipt, wrong period); approved claims are paid with salary or in a separate payment, and Finance is told.

## Build
1. **Categories and policy (EXP-01).** Category with limit by grade (policy type `expense`), per-diem and mileage rate rules (customer values), receipt requirement, tax-treatment label, reimbursement component.
2. **Claims (EXP-02, Q1).** Header and lines: date, category, amount, currency, project and cost-centre coding, receipt upload (file store, scan); multi-currency lines converted at the rate on a customer rate table recorded on the line; save draft, submit, withdraw.
3. **Policy checks (EXP-03).** At submit: over limit, duplicate receipt (file checksum plus amount and date), missing receipt, outside the claim window (setting); flags shown to the claimant and the approvers; flags never block submit unless the category says so.
4. **Approval (EXP-03).** Workflow manager then finance by amount thresholds (settings); partial approval per line with reason; nobody approves their own.
5. **Reimbursement (EXP-05).** Choice per claim: payroll (a `pay_inputs` row for the period through the provider) or separate payment batch (S1.40a); status returns to the claim (paid, failed).
6. **Event (EXP-06).** `hrm.expense_claim.approved` in the outbox with totals by category and coding.
7. **Screens.** Categories, claim form, my claims, approvals card with flags, finance list; English and Urdu.

## Acceptance
- Each flag has a failing example; duplicate receipt across two claims is detected; per-line approval pays only approved lines.
- Payroll route creates exactly one input per claim line set and marks it consumed after the run; separate batch route updates claim status from the payment line.
- FR-XM-29 query returns unsubmitted and unpaid claims for an employee. GHR-06 holds. Tenant-isolation test for every endpoint; FR ids in tests.

## Questions (recommendations are rulings, CR-083)
- **Q0 Single part.** *Recommendation:* one part.
- **Q1 Receipts.** *Recommendation:* web upload only now; the capture path is reserved for the mobile slices.
- **Q2 Rates.** *Recommendation:* per-diem and mileage rates are customer data in the policy; none shipped.
- **Q3 Currency rates.** *Recommendation:* customer rate table `hrm.exchange_rates` with date; the rate used is stored on the line.
- **Q4 Window.** *Recommendation:* setting `hrm.exp.claim_window_days`, default none.
- **Q5 Thresholds.** *Recommendation:* approval steps by amount from settings, finance step optional.
- **Q6 Change request CR-098.** *Recommendation:* approve: policy type `expense`; table `hrm.exchange_rates` if absent; settings `hrm.exp.claim_window_days`, `hrm.exp.finance_threshold`; event `hrm.expense_claim.approved`; document type `hrm.expense_claim`; expand-only.
