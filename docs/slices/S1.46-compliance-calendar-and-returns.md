# S1.46 Compliance calendar, statutory registers and returns, tax certificates
Status: APPROVED by the standing ruling (CR-083): every recommendation (Q0 to Q6) is the ruling; CR-102 approved. Reserved numbers: CR-102, R-191 to R-192.
Class: C        Model: **Sonnet 5.5, medium effort**. No fresh review. **Statutory formats are pack content**: build the mechanism; every official layout waits for the payroll and tax professional (AS-4, R-002).
Parts (Q0): **S1.46a** compliance calendar, obligations, tasks, reminders, generic registers (items 1 to 4); **S1.46b** returns from pack templates and tax certificates (items 5 to 7). One session and pull request per part; part b is built only when the professional's formats exist.
Requirements (all release 1.0): FR-HRM-CPL-01 (compliance calendar: deadlines per entity, owners, reminders, completion), CPL-02 (registers and returns in prescribed formats: muster roll, wage register, EOBI lists, social security returns, withholding tax statements, annual employee tax statement; the **prescribed layouts are pack data**, Q2),
CPL-04 (formats in country packs, staged releases), CPL-05 (employee tax certificates and annual statements in self-service), FR-HRM-POL-04 and -06 (pack, tenant overrides), GHR-08 (staged pack releases with impact preview), GHR-15, GHR-06.
Not built here: any official statutory layout, rate or threshold in code; e-filing to authorities (Later); payroll calculation (S1.36, S1.37).

Depends on: S1.23b, S1.23c, S1.35b, S1.38, S1.11c2; part b also S1.36, S1.37.

## Goal
The company's compliance officer sees every statutory deadline with who owns it and whether it is done, gets reminders, and produces the registers and returns the authorities require from payroll data in the authority's layout. Employees download their annual tax statement.

## Build
### Part S1.46a
1. **Obligations and calendar (CPL-01).** Obligations (authority, recurrence, owner role, return template) from packs or tenant; generate tasks per period and entity; status, completion with proof file, overdue flags; calendar view and list; reminders as notification events (`hrm.compliance.due`); a pack provides none here until validated, the customer may add their own.
2. **Generic registers (CPL-02 part).** Muster roll and wage register as data views over attendance and payroll results (no statutory layout): columns chosen by a template; export through S1.16.
3. **Pack integration (CPL-04, GHR-08).** Return templates arrive through the pack object handler; staged pack release shows an impact preview (which returns change); tenant override and diff view (POL-06).
4. **Screens.** Calendar, task list, register runner; English and Urdu.
### Part S1.46b
5. **Returns (CPL-02).** Generate EOBI contribution lists, social security returns and withholding statements from `statutory_returns` templates (data: field sources, layout, file type) over locked results; each generation records source run ids and a document; regeneration after a correction creates a new version.
6. **Tax certificates (CPL-05).** Annual employee tax statement and certificate generated per tax year from S1.36 results, bilingual, visible in self-service for the employee only; HR generates for all in bulk with a job.
7. **Verification.** Each return template ships with a test pack file and expected output provided by the professional; none exists until then.

## Acceptance
- CPL-01: obligations produce tasks for each period; a reminder event is raised before the due date; completion needs a proof file; overdue appears on the HR workspace queue.
- CPL-04: a staged pack update shows the impact preview and keeps a tenant override.
- Part b (when formats exist): each return reproduces the professional's expected output exactly; a tax certificate equals the S1.36 result totals; an employee sees only their own.
- Tenant-isolation test for every endpoint; permission tests; FR ids in tests.

## Out of scope
See "Not built here".

## Questions (recommendations are rulings, CR-083)
- **Q0 Parts.** *Recommendation:* two parts; part b waits for validated formats and S1.36 and S1.37.
- **Q1 Reminder lead times.** *Recommendation:* per obligation days before, customer values.
- **Q2 Formats.** *Recommendation:* template data only; no layout is written from memory.
- **Q3 Generic registers.** *Recommendation:* neutral muster roll and wage register now; the official variants replace them through the pack.
- **Q4 Certificates.** *Recommendation:* generated only for closed tax years or on demand with a "provisional" mark.
- **Q5 Authority list.** *Recommendation:* the customer chooses their authorities; none is preselected.
- **Q6 Change request CR-102.** *Recommendation:* approve: event `hrm.compliance.due`; template types `statutory_return`, `tax_certificate`; job `hrm.tax_certificates_generate`; pack object type `statutory_return_template`; expand-only.
