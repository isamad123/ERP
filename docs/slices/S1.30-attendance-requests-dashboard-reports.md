## Goal
An employee who forgot to punch asks for a correction with a reason and proof; their manager approves; the day is recalculated. Field staff and people on official visits
or working from home raise duty requests that count as present. Managers and HR see who is in, late, absent or on leave right now, and download the standard attendance reports.

## What exists already (and stays)
Tables above (generated reads), the engine and exception queue (S1.29), workflow engine, list and form engine, reporting views patterns (S1.12c).

## Found while preparing (needs a ruling)
1. Duty request kinds and whether each counts as present are policy choices (Q1). 2. Proof attachments need the file store (S1.11c1; available). 3. Dashboard "not yet punched" needs the shift start (S1.28) (Q2). 4. Reports must hide pay data and respect scopes (Q3).

## Build
### Part S1.30a
1. **Regularization (ATT-11).** From an exception or a date: requested in and out times, reason, files; routes through workflow (`hrm.regularization`); approval writes a correction event (new event referencing the original, source `regularization`) and re-queues the day; rejection keeps the exception open.
2. **Duty requests (ATT-14, Q1).** Kinds `on_duty`, `official_visit`, `work_from_home`, `field_duty`; period (start, end), purpose; approval makes affected days "on duty" through the engine; counting as present is a flag per kind in the `attendance` policy.
3. **On behalf (GHR-09).** Managers and HR submit for others; acting user stored; never approved by the same person.
4. **Screens.** Exception queue (filters by unit, kind, age), my requests, request forms, approval cards in the shared inbox; English and Urdu.
### Part S1.30b
5. **Live dashboard (ATT-18, Q2).** Counts present, absent, late, on leave, not yet punched by unit and location for today, refreshed on load and every N seconds (setting); drill down to the list; data scope applies.
6. **Reports (ATT-19, RPT-05).** Muster (daily, monthly), late and early, overtime, absenteeism, punch log, device sync, exception ageing; filters, saved views, export through S1.16; read-only database views that apply data scopes and hide pay fields.
7. **Manager views (SSP-02).** Team attendance today and this month; widget registered for the S1.26 home page.
8. **Query performance.** Indexes for the dashboard counts; test with 10,000 employees and one month of days (under 2 seconds per view).

## Acceptance
- ATT-11: forgot-to-punch scenario: request, approve, day becomes present, exception closed, original event untouched; own request cannot be approved.
- ATT-14: a field-duty request for three days makes those days "on duty" and present when the policy flag says so.
- ATT-18: dashboard counts equal list counts on a test dataset; a manager sees only their scope.
- ATT-19: each report returns expected rows and totals on the 30-scenario dataset of S1.29; no pay field is exposed without permission.
- Every screen: accessibility, keyboard only, Urdu right to left, 360, 768, 1280 px, loading, empty, error, denied states, screenshots; tenant-isolation test for every endpoint; FR ids in tests.

## Questions (recommendations are rulings, CR-083)
- **Q0 Parts.** *Recommendation:* two parts.
- **Q1 Duty kinds.** *Recommendation:* the four kinds, each with a policy flag "counts as present" (default yes for on duty, official visit and field duty; work from home per customer).
- **Q2 Not yet punched.** *Recommendation:* employees with a shift today whose start time plus the grace has passed and no punch; others show as "not due".
- **Q3 Reporting views.** *Recommendation:* database views per report, scope applied in the service layer exactly as other list endpoints; no pay fields in any attendance view.
- **Q4 Refresh.** *Recommendation:* the dashboard polls (setting `hrm.att.dashboard_refresh_seconds`, default 60); no push in 1.0.
- **Q5 Proof types.** *Recommendation:* the file store limits and scan apply; images and PDFs only by default.
- **Q6 Change request CR-090.** *Recommendation:* approve: document types `hrm.regularization`, `hrm.duty_request` in `workflow.json`; setting `hrm.att.dashboard_refresh_seconds`; policy field `counts_as_present` per duty kind; reporting views `rpt.att_*`; expand-only.
