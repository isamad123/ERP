## Goal
Given a pay group and period, the engine freezes everything it will use (employee records, structures, attendance, tables, rule versions), calculates every employee's earnings, deductions and
employer costs, and stores results that explain themselves. Running it again on the same frozen data gives the same numbers to the last paisa. It handles thousands of employees in chunks,
survives a restart, and never edits a locked result.

## What exists already (and stays)
Pay set-up (S1.34), job runner with checkpoints (S1.11a), tables above (generated reads; writes only through the engine), numbering, audit rules (`hrm.pay_traces` unaudited).

4. **Snapshot size** for 50,000 employees (Q4). 5. **Input import** from files runs through the S1.16 import centre (Q5).

## Build
### Part S1.35a
1. **Input provider contract (PAY-07, Q5).** `IPayInputProvider` (employment, period) returns typed inputs; implementations: attendance and leave (locked), overtime, lateness deductions, bonuses and manual adjustments from `hrm.pay_inputs`;
   loans and expenses providers arrive with S1.41 and S1.42; imported files create `pay_inputs` rows through the import centre; consumed inputs are marked with the run.
2. **Lock first (FR-XM-26).** Starting a calculation calls `IAttendancePeriodLock.Lock`; refuses when it cannot.
3. **Snapshot (PAY-31, Q4).** Per employee: employment and assignment facts, pay group, compensation lines, structure and component versions, attendance and leave totals, inputs, table and rule version ids, policy versions; stored compressed in `pay_run_employees.snapshot` with `snapshot_hash` (SHA-256 of canonical JSON); run `snapshot_taken_at`.
4. **Formula evaluator (PAY-03, Q1).** Grammar: numbers, component codes, named inputs (`worked_days`, `paid_days`, `period_days`), `+ - * /`, parentheses, `min`, `max`, `round`, `if(cond, a, b)` with comparisons; decimal arithmetic only (`numeric(19,4)` semantics, banker's or half-up per Q3); no loops, no function calls beyond the list, no I/O; fully parsed at definition time by the same code behind `IFormulaValidator`.
5. **Calculation (PAY-03, PAY-05).** Components in structure order; each method (fixed, percentage, formula, table lookup, per-day, per-hour, attendance-linked, manual); pro-rata by the component version's rule; produces `pay_results` and `pay_result_lines`; employer cost and net; money rounding per Q3.
6. **Statutory plug-in point (Q2).** `IStatutoryCalculator` called per component marked statutory with the snapshot and returns amounts and trace lines; with none registered, components marked statutory make the employee "incomplete" and the run refuses to finish (never silently zero).
7. **Immutability (PAY-33).** Results of a locked run: database refuses update and delete (guard trigger, rules.yaml `functions`); a correction is a new result with `corrects_result_id` in a later run (S1.39 uses this); run `kind` regular only here.
### Part S1.35b
8. **Trace (PAY-32).** For every result: inputs used, formula text and evaluated steps, table and rule versions, rounding applied, engine version; stored in `hrm.pay_traces` (not audited, field class restricted); read endpoint needs `hrm.pay.trace.read`.
9. **Chunked resumable job (PAY-34).** Job `hrm.payroll_calculate`: chunks of N employees (setting), each chunk commits results and its checkpoint together; restart continues from the checkpoint; cancel; progress percentage and counts; the run's stage log records start, end, user.
10. **Determinism and performance tests (PAY-31, GHR-01).** Same snapshot calculated twice and after a mid-run restart gives byte-identical result and trace hashes; 10,000-employee run (synthetic, ten components) finishes under 15 minutes on the CI machine class recorded in the test; memory bounded.
11. **Recalculation hook.** `Recalculate(run, employments)` recomputes the listed employees from their existing snapshots or a fresh one on request (the stage rules are S1.38); previous unlocked results are replaced as new row versions, history kept.

## Acceptance
- PAY-03: each method has a worked example whose expected value is computed independently in the test (no statutory numbers); a formula with a forbidden construct is refused at definition time.
- PAY-31: determinism test as above; changing one input changes the snapshot hash and only that employee's result.
- PAY-33: update and delete of locked results refused by the database for every login; a correction creates a new row linked to the original.
- PAY-32: the trace for a sample result lists every step; a user without `hrm.pay.trace.read` gets 403; the trace never appears in audit search.
- PAY-34: kill the worker mid-run, restart, finish; counts equal an uninterrupted run; performance test within the limit.
- FR-XM-26: calculation locks the period first; with open exceptions it refuses unless the flag is passed.
- GHR-06: no amount visible without permission in API, list, export or audit. Tenant-isolation test for every endpoint; fresh Opus review per part.

## Questions (recommendations are rulings, CR-083)
- **Q0 Parts.** *Recommendation:* two parts, Opus, fresh review each.
- **Q1 Grammar.** *Recommendation:* as item 4; hand-written parser and evaluator, no package; the grammar is versioned (`engine_version`) and stored in each trace.
- **Q2 Statutory plug-ins.** *Recommendation:* `IStatutoryCalculator` registered by S1.36 (tax) and S1.37 (contributions); no statutory component is ever calculated by this slice.
- **Q3 Rounding.** *Recommendation:* all arithmetic in decimal; round half away from zero to 4 places internally and to the pay group's currency minor units on result lines; mode in the pay group setting.
- **Q4 Snapshot storage.** *Recommendation:* JSON compressed per employee row; a run's snapshots are kept with the run for audit and purged only with the run's retention.
- **Q5 Input import.** *Recommendation:* the import centre (S1.16) maps file columns to `pay_inputs`; this slice offers the validated bulk insert endpoint and the template.
- **Q6 Parallelism.** *Recommendation:* chunks processed by up to N workers (setting); each employee independent.
- **Q7 Currencies.** *Recommendation:* one currency per run; a different currency component is converted by a rate recorded in the snapshot (rate source is a pack or customer table).
- **Q8 Posting stub (D-43, FR-XM-27).** *Recommendation:* the run publishes `hrm.pay_run.calculated` only; the journal event comes at finalize (S1.38) and export (S1.45).
- **Q9 Permissions.** *Recommendation:* `hrm.pay.run`, `hrm.pay.trace.read`, `hrm.pay.results.read`; maker-checker for run start is S1.38.
- **Q10 Change request CR-093.** *Recommendation:* approve: contracts `IPayInputProvider`, `IStatutoryCalculator`, `IFormulaValidator` (completed); job `hrm.payroll_calculate`; settings `hrm.pay.chunk_size`, `hrm.pay.max_parallel_chunks`, `hrm.pay.rounding_mode`;
  permissions above; guard trigger on locked results; event `hrm.pay_run.calculated`; expand-only.
