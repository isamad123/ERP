Status: APPROVED by the standing ruling (CR-083): every recommendation (Q0 to Q6) is the ruling; CR-106 approved. Reserved numbers: CR-106, R-199 to R-200.
Class: D        Model: **Sonnet 5.5, medium effort**. No fresh review.

Depends on: S1.20b, S1.22b, S1.25b, S1.30b, S1.32b, S1.16.

## Goal
HR leaders open one place and see headcount, who joined and left, the make-up of the workforce, attrition, today's attendance, leave liability and upcoming contract and probation ends, and can download the standard HR reports, all respecting what each user may see.

## Build
1. **Report catalogue.** A registry of standard reports and dashboard tiles (code, name keys, permission, source view, filters, export formats); other slices register theirs.
2. **Views (RPT-04, Q1).** Read-only database views `rpt.hr_*` for each report, applying data scope in the service layer like list endpoints; salary-bearing columns removed unless the user holds the salary permission; as-of date parameter where effective-dated.
3. **Dashboards (RPT-01).** Tiles for headcount by unit and grade, joiners and leavers by month, age and gender mix, attrition rate (leavers over average headcount, formula shown), leave liability (units and, with salary permission, value), contract and probation expiries in the next N days; drill-down to lists; refresh on load.
4. **Reports (RPT-02).** Employee master, strength by unit, grade and location, movements (hires, transfers, promotions, exits), birthdays and anniversaries, document expiry, leave balance and utilization, attendance summaries (links to S1.30 reports); filters, saved views, export through S1.16.
5. **Performance.** Indexes and a 50,000-employee test dataset: each tile and report under 3 seconds.
6. **Screens.** Dashboard page, report list and runner; English and Urdu; accessible charts with table alternatives (design-system chart components, no other library).

## Acceptance
- Each dashboard tile equals the count from its drill-down list on a seeded dataset; a manager sees only their scope.
- RPT-04: a user without salary permission gets no salary column in view, API, export or audit search; with permission, values appear.
- As-of reports reproduce a past month's headcount after later changes.
- Performance test within the limit; tenant-isolation test for every endpoint; FR ids in tests; axe checks on charts.

## Out of scope
See "Not built here".

## Questions (recommendations are rulings, CR-083)
- **Q0 Single part.** *Recommendation:* one part.
- **Q1 Views.** *Recommendation:* views plus service-layer scope, as in S1.30; no row-level security (D-47).
- **Q2 Attrition formula.** *Recommendation:* leavers in period divided by average of opening and closing headcount, shown on the tile.
- **Q3 Leave liability value.** *Recommendation:* units for everyone; value only with salary permission and only from S1.44 accruals.
- **Q4 Charts.** *Recommendation:* the design-system chart set (S1.12a); no new charting package.
- **Q5 Scheduling.** *Recommendation:* none in 1.0.
- **Q6 Change request CR-106.** *Recommendation:* approve: registry `report-catalogue.json` per module; views `rpt.hr_*`; permissions `hrm.reports.hr.read`; expand-only.
