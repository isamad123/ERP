# S1.03 Control plane, tenant resolution, provisioning and migrator
Class: B        Model: Opus 5.5 (high effort); fresh Opus session reviews the diff
Requirements: KRN-TEN-01, 02, 03, 04, 09; ADM-PLT-01, 02, 03, 10, 11; ADM-DAT-08. Decisions: D-02, D-47.
Spec to read: `docs/data-design/control-plane.yaml`; `docs/specs/02-…` section 3 (TEN) only.
Depends on: S1.02.

## Goal
One control-plane database lists customers; each customer gets its own PostgreSQL database created from the generated
migrations; every request is bound to exactly one customer database.

## Build
1. Control-plane migrations from the generator; seed one platform admin from environment variables.
2. `ITenantContext` and `ITenantConnectionProvider`: resolve the tenant from host name (`cp.tenant_domains`) or from
   the signed token; never from request body, query string or a client header. Unknown host returns 404.
3. Connection management with pooling per tenant database and statement timeouts.
4. Provisioning: create database, apply kernel and licensed module migrations, seed baseline data (default company,
   branch, roles, settings), create first tenant admin with an invitation; idempotent and resumable; recorded in
   `cp.platform_audit`.
5. Migrator command: apply pending migrations to all tenant databases one by one; a failure marks that tenant
   `maintenance` and continues with the others; results recorded.
6. Tenant states: suspended or locked tenants get read-only or no access as defined by the entitlement state.
7. Per-tenant backup and restore scripts (pg_dump/pg_restore) with a documented drill.

## Acceptance
- Two tenants provisioned; data written in one is never visible in the other (integration test through the API).
- Request with a forged host or token is refused.
- Re-running provisioning after a forced failure completes without duplicates.
- Backup of one tenant restored into a new database and verified.

## Out of scope
Fleet canaries and moving tenants between servers (1.1), sandbox environments (1.1), licence files for on-premises.
