## Goal
Bring data in and take it out safely. An administrator downloads a template, fills it in a spreadsheet, uploads it, sees
every problem row before anything is saved, commits the good rows in the background and can undo a batch that only added
records. Anyone may export what they are allowed to see from any list, with sensitive exports explained and logged. An
operator-minded administrator sees jobs, messages, health, backups and the licence in plain screens.

## What exists already (and stays)
- Jobs: definitions, runs, logs, rerun, cancel, schedule (`/api/jobs/*`), chunked resumable handlers (`IJobHandler`), the
  worker; health figures (`/api/jobs/health`).
- Notification deliveries, summary and resend (`/api/ntf/deliveries*`).
- Licence state and usage (`GET /api/cfg/licence`, `/licence/usage`; answer in locked state).
- File store with per-customer encryption, scan hook and retention (S1.11c1).
- Audit export (`/api/aud/export`, capped at 10,000 rows per request, S1.07) and the access log.
- Tables `itg.import_*` and `itg.export_jobs` exist with generated read endpoints; no engine uses them.
- Backups and restore drills are recorded in `cp.platform_audit` (`TenantLifecycle.RecordBackupAsync`).

## Found while preparing (needs a ruling)
1. **Formats.** FR-KRN-INT-03 lists CSV, Excel, JSON and XML; the approved data design allows `csv` and `xlsx` (and `pdf`
   for exports) (Q2).
2. **Licence upload is for on-premises installations**, whose package (FR-KRN-TEN-07) is 1.1; in SaaS the licence comes from
   the vendor console (Q10).
3. **"Slow queries summary"** (FR-ADM-OPS-05) needs a database extension that is not in the approved stack (Q11).
4. **Spreadsheet formula injection.** A cell starting with `=`, `+`, `-` or `@` opens as a formula in Excel; exports of
   user-typed text must neutralise it (Q7).

## Build
### Part S1.16a: imports
1. **Import types (D-10).** Each module declares its import types in `<module>.Infrastructure/Access/imports.json`
   (table, key columns for "update by code", columns with lookups by code, permission); seeded like jobs (`ImportSetup`).
   First types: users (creates invited users and sends invitations; never passwords), org units (with parent by code and
   hierarchy, through the S1.14 move rules), holidays, locations.
2. **Import engine (FR-KRN-INT-03, -04).** Upload (file store, scan hook, size and row limits), read CSV and Excel by
   streaming, map columns by template, transform (trim, case, date and number formats, lookups by code, defaults), validate
   every row through the same services as manual entry (access, scope, field security, custom fields of S1.15b) in a
   **validation run that saves nothing**, then commit as a chunked resumable job (audit source `import`, one batch id).
   Duplicates: a row whose key exists is an update when the template says "create or update", otherwise an error.
3. **Rollback (Q5).** A batch that only created rows can be rolled back within `itg.import.rollback_days` (default 7) if
   none of its rows changed since; rolled-back rows are deleted or soft-deleted as their table allows; otherwise the screen
   explains why not.
4. **Import centre (FR-ADM-DAT-01).** Choose type and template, download the template file (headers, an example row and a
   sheet of allowed values), upload, see the validation summary and the first 100 problems on screen, download the full
   error file (original row plus a message column), commit, watch progress, roll back.
5. **Template designer (FR-ADM-INT-04).** Map source columns to fields, set transformations and defaults, test with a sample
   file (validation only), save and version templates; the product ships one default template per type.

### Part S1.16b: exports
6. **Export engine (FR-ADM-DAT-04).** An export is a job over a generated list query with the caller's filters, sort and
   columns; the caller's permission, data scope and field security apply row by row (hidden fields left out, masked fields
   exported masked); CSV or Excel; file kept in the file store for `itg.export.keep_days` (default 7); every export logged
   in `itg.export_jobs`; sensitive field classes recorded in the access log.
7. **Rules (Q6, Q7, Q8).** Row limit `itg.export.max_rows` (default 50,000); a reason is required when the export contains a
   sensitive field class; an export above `itg.export.approval_rows` (default 5,000) or with sensitive fields waits for a
   second person when maker-checker is on; the file carries a watermark line (who, when, customer) and neutralised
   formula cells.
8. **Export from every list and the export centre (FR-ADM-NAV-02).** The list engine's reserved export button (current
   view), the user list bulk export (S1.13), the audit search's large exports as jobs; the export centre lists one's own
   exports (and everyone's for holders of `itg.export_jobs.read` at company scope) with status and download; allowed in
   read-only and locked states.

### Part S1.16c: operations
9. **Job centre (FR-ADM-OPS-01).** Definitions with schedule editing for permitted jobs, runs with filters (status, job,
   date), progress, logs, result download, rerun, cancel.
10. **Notification log (FR-ADM-OPS-04).** Messages with status (queued, sent, failed, bounced), retries, failure reason,
    resend; summary per day.
11. **System health (FR-ADM-OPS-05, Q11).** Worker status, queue depth, oldest waiting job, outbox lag, failed and stuck jobs,
    files not scanned, storage used, database size, last backup; alert subscription links to the notification rules (S1.15).
12. **Licence and usage page (FR-ADM-OPS-07, Q10) and backup status (FR-ADM-DAT-08, Q12).** Edition, modules, limits and
    consumption with warnings, term and maintenance dates, state with what it means, next state and when; monthly usage
    statements; last successful backup and last verified restore drill.

## Acceptance
- An administrator imports 500 users from the template; the validation run finds 12 bad rows (error file downloaded), saves
  nothing; after fixing, the commit creates 500 invited users and sends 500 invitations (`TestMailServer`); seat
  consumption rises; the batch rolls back while untouched and is refused after one of its users activated.
- A 50,000-row holiday or unit file is validated and committed in the background with progress; stopping the worker
  mid-way and starting it again finishes the batch without duplicates (FR-KRN-INT-04).
- An import of units by a company administrator scoped to one company refuses rows of another company.
- An uploaded file that the scan hook marks infected is refused before reading; an Excel file over the size or row limit
  is refused with a clear message.
- A user with masked salary-class fields exports a list: the file has them masked, a reason was asked, the access log has
  the export; above the approval threshold with maker-checker on, the export waits for a second person; a cell `=1+1`
  exports as text; a locked customer can still export.
- Job centre reruns a failed job and cancels a running one; the notification log resends a failed message; the health page
  shows outbox lag and the last backup; the licence page shows state, limits and the usage statement.
- Every screen: accessibility, keyboard, English and Urdu, three widths, states, screenshots.
- New endpoints pass the tenant-isolation suite and have permission tests; tests cite the FR ids.

## Out of scope
Everything under "Not built here". PDF exports (Q2). Imports of employees, pay data and attendance (their slices add types).

## Questions as put to the product owner
- **Q0 Parts and review.** *Recommendation:* three parts (a imports with a fresh Opus review because it reads uploaded
  files; b exports; c operations screens). Alternative: two parts (b and c together).
- **Q1 Menu.** *Recommendation:* group "Administration": "Imports", "Exports", "Jobs", "Notification log", "System health",
  "Licence and usage". Alternative: an "Operations" group.
- **Q2 File formats.** *Recommendation:* CSV (UTF-8, comma or semicolon) and Excel (.xlsx) for import and export, as in the
  approved data design; JSON and XML through the API only; PDF exports later with reports (S1.51). CR-072 records the
  narrowing for 1.0. Alternative: add JSON and XML files now.
- **Q3 Spreadsheet packages (D-09; licences to be checked by the gate at build).** *Recommendation:* Sylvan.Data.Csv and
  Sylvan.Data.Excel (MIT; streaming read and write, low memory for 50,000 rows). Alternative: ClosedXML (MIT; loads the
  whole workbook into memory).
- **Q4 Import types in 1.0 of this slice.** *Recommendation:* users, org units, holidays and locations; each later module
  slice adds its own (employees in S1.21). Alternative: users only.
- **Q5 Rollback "where feasible".** *Recommendation:* only batches that created rows, within 7 days, and only while none of
  those rows changed; update batches cannot be rolled back (the error and change files say what changed). Alternative: no
  rollback in 1.0.
- **Q6 Export limits and approval.** *Recommendation:* settings `itg.export.max_rows` 50,000, `itg.export.approval_rows`
  5,000, `itg.export.keep_days` 7; approval uses maker-checker (FR-KRN-IAM-14 "bulk export"). Alternative: no approval
  in 1.0 (reason and log only).
- **Q7 Watermark and formula cells.** *Recommendation:* the first line (CSV) or a header row and the sheet footer (Excel)
  say "Exported by <name> on <date> from <customer>; confidential"; cells that start with `=`, `+`, `-` or `@` are
  written as text. Alternative: no watermark line (some customers re-import exports).
- **Q8 Sensitive exports.** *Recommendation:* a reason is required when the export contains any field of a sensitive class
  (salary, national id, bank); the reason is stored with the export and in the access log. Alternative: a reason for every
  export.
- **Q9 Who sees others' exports.** *Recommendation:* each person sees their own exports; holders of `itg.export_jobs.read`
  see those of their companies, without downloading others' files. Alternative: administrators may download others' files.
- **Q10 Licence file upload.** *Recommendation:* not in 1.0: SaaS licences change in the vendor console (S1.17); upload
  arrives with the on-premises package (FR-KRN-TEN-07, 1.1). CR-072 records it. Alternative: build upload now (licensing
  code, class B, Opus).
- **Q11 Slow queries.** *Recommendation:* left out in 1.0 (needs `pg_stat_statements`, not in the approved stack); the page
  shows the other figures. Alternative: add the extension (decision needed).
- **Q12 Backup status.** *Recommendation:* read-only: last successful backup and last verified restore drill from the control
  plane, for tenant administrators; start, schedule and restore-to-sandbox actions are on-premises features (1.1).
  Alternative: none.
- **Q13 Urdu texts.** *Recommendation:* drafted in the session and marked for a native speaker's review (R-062).
- **Q14 Change request CR-072.** *Recommendation:* approve: import manifests `imports.json` and `ImportSetup`; formats CSV
  and Excel only (Q2); packages of Q3 recorded in `docs/registers/dependencies.md`; settings of Q5 and Q6; licence upload
  and backup actions moved to 1.1 (Q10, Q12); slow queries left out (Q11); contracts register rows added at build.
