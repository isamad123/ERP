## Goal
An employee picks a leave type and dates (or part of a day), sees what their balance will be after the request, attaches a document if the type needs one, and submits. The manager sees
the request with a coverage warning showing who else in the team is away. HR defines leave types and rules, reads any employee's ledger with the reason for every number, previews and
confirms year-end, and applies leave on someone's behalf.

## What exists already (and stays)
Leave APIs of S1.32, policy screens (S1.23), workflow inbox (S1.12d), portal host (S1.26), file store.

## Found while preparing (needs a ruling)
1. Coverage warning needs a definition (Q1). 2. A balance-impact preview needs a no-write endpoint from S1.32 (Q2). 3. Calendar colours and legends must work in dark mode and Urdu (Q3).

## Build
### Part S1.33a
1. **Apply for leave (LVE-04, LVE-16).** Form: type, from, to, first and last day part (full, first half, second half), hours for hourly types, reason, attachment (upload; the type says if required); shows days counted by the server rules, balance before and after, and every refusal reason in plain words.
2. **My leave.** Balances per type with "why" (opens the ledger entries), requests with status and cancel or modify buttons (S1.32b rules).
3. **Approvals cards (LVE-05).** Request card in the shared inbox: employee, dates, days, balance after, document, coverage warning, decision and comment; HR "apply on behalf" with the employee picker, acting user shown.
4. **Team calendar (LVE-15, Q1).** Month grid of the manager's scope: leave by person, holidays, weekly offs, with a coverage bar ("3 of 8 away on 14 March; limit setting 30 percent"); filters; keyboard navigable; print.
5. **Portal and manager widgets.** Register "my balances", "team away today" for the S1.26 home page.
### Part S1.33b
6. **Leave types and policies (LVE-01, LVE-03).** List and form over the types; policy editor for the `leave` policy type with grouped sections and validation messages from the schema; preview "who does this apply to" through S1.23.
7. **Ledger and recompute (LVE-10, LVE-14).** Employee ledger with filters, source documents as links, running balance; "recompute" runs the S1.32 job and shows differences with their explanation.
8. **Year-end (LVE-11).** Run list; preview table by employee and type (carry-forward, lapse, encash); confirm with approval where set; rollback until confirmed.
9. **Reports.** Balance summary by unit, leave taken by type and month, pending requests, with export through S1.16.

## Acceptance
- LVE-04: half-day request over a holiday shows the right count and balance after; hourly leave on an hourly type; a missing required document blocks submit with a clear message.
- LVE-05/15: the manager card shows the coverage warning; the calendar matches the S1.32 day lists for a test month; HR on behalf records the acting user.
- LVE-10/14: every balance number opens its entries; a planted difference shows in the recompute screen.
- LVE-11: preview then confirm then rollback-before-confirm path through the screens.
- Every screen: accessibility, keyboard only, Urdu right to left, 360, 768, 1280 px, loading, empty, error, denied states, screenshots in both languages and themes; tenant-isolation test for new endpoints; FR ids in tests.

## Questions (recommendations are rulings, CR-083)
- **Q0 Parts.** *Recommendation:* two parts.
- **Q1 Coverage.** *Recommendation:* percentage of the manager's direct and indirect team on leave that day against a setting `hrm.leave.coverage_warning_percent` (default 30); a warning only, never a block.
- **Q2 Preview.** *Recommendation:* S1.32 exposes `POST /api/hrm/leave-requests/preview` (no write) used by the form; added in this slice's server task if S1.32 lacks it.
- **Q3 Colours.** *Recommendation:* design tokens only; leave types carry a token name, never a raw colour.
- **Q4 Print.** *Recommendation:* browser print stylesheet for the calendar; no server PDF.
- **Q5 Reports.** *Recommendation:* views over scoped list endpoints; no new report engine.
- **Q6 Change request CR-092.** *Recommendation:* approve: setting `hrm.leave.coverage_warning_percent`; preview endpoint if missing; token column on leave types if missing; expand-only.
