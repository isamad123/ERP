## Goal
HR builds a form from a few building blocks (section, rating scale, text, choice, number, yes or no, competency with weight), publishes a version, and uses it for an appraisal or a probation review. Responses are stored per person and version; a published version never changes.

## Build
1. **Definitions and versions.** Form with purpose (`appraisal`, `probation_review`, `goal_review`, `custom`: the values of `hrm.form_definitions.purpose`); draft versions edited in a list-based builder (add, order, remove blocks; no drag canvas); publish makes a version immutable; new edits create a new version; retire a form.
2. **Blocks.** Section, text, long text, choice, multi-choice, yes or no, number with range, rating scale (named scales, customer values), competency (title, description, weight, scale); mandatory flag; help text; English and Urdu labels.
3. **Responses.** Start a response for an employment against a version, save draft, submit, return for correction; mandatory checks; weighted score computed in decimal when weights exist; answers stored as typed JSON validated against the version; responses never change after sign-off.
4. **Probation contract (R-020).** `IFormResponseService` (start, submit, read summary) used by the onboarding probation review; field classes carry through (ratings are sensitive personal).
5. **Screens.** Form list, builder, preview, response form (the same engine for employee, manager and HR roles with section-level access); English and Urdu, accessibility checks.

## Acceptance
- A published version cannot be edited (API and database); an edit creates version 2 and old responses keep version 1.
- Mandatory and range checks block submit with messages in both languages; the weighted score matches a hand computation.
- The probation review of S1.25 completes through the contract; section-level access hides manager sections from the employee.
- Tenant-isolation test for every endpoint; FR ids in tests (PRF-03, ONB-12).
