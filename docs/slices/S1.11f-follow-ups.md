## S1.11f1 (Sonnet 5.5)
1. **Time-zone check (R-019, Q4a).** `org.time_zone` accepts any text today; the resolver and numbering skip an unknown
   zone silently. Add a `time_zone` format rule to setting validation (a new validation key; never edit a merged
   manifest entry in a way the checksum or snapshot tests forbid: follow `docs/handoff/2026-11-17-S1.09a.md`). An
   unknown IANA zone is refused with a localized error (English and Urdu). Tests cite the FR id.
2. **Secret scan in CI (R-030, Q9 a).** Add an automated secret scan to `.github/workflows/ci.yml` that fails the build
   on a finding. Use a tool with a permissive licence (D-09), record it in `docs/registers/dependencies.md`, and make the
   licence gate aware of it if it checks CI tools. The CI-only test password `erp-ci-only` is acceptable and may be
   allow-listed by exact value. Update CLAUDE.md "Not yet automated" and the done-criteria line.
3. **Invariant traits (R-030, Q9 c).** Add `[Trait("Invariant", "n")]` to the existing tests of invariants 3, 5, 8 and 9
   (6 and 10 are already tagged). Tagging only: do not change what a test asserts. Update the CLAUDE.md invariants line.

Acceptance: build with 0 warnings; the full suite; the secret scan runs in CI and fails on a planted secret in a
throwaway test commit (not merged); `--filter-trait "Invariant=3"` (and 5, 8, 9) each run at least one test.

## S1.11f2 (Opus 5.5, high effort)
4. **Control-plane migration history (CR-006, Q5).** Add `cp.schema_history` (same shape as `meta.schema_history`) to
   `docs/data-design/control-plane.yaml` by change request, generate the migration, and make the control-plane
   migrator record and checksum-check its scripts like `TenantSchemaMigrator`. Existing control-plane databases that
   already ran the idempotent scripts must migrate cleanly (record the existing scripts on first run).
5. **One open workflow request per document (R-023, Q4c).** A new migration adds a partial unique index on
   `wf.workflow_instances (document_type, document_id) where status in ('running', 'returned')`, through the data
   design (expand only). Test: a write that bypasses the engine cannot open a second request.
6. **Same customer provisioned twice at once (R-031).** Two runs for the same customer code must not both proceed: take a
   per-customer advisory lock in the control-plane database around provisioning (or an equivalent the plan justifies),
   so the second run waits and then resumes or stops cleanly. Tests use real PostgreSQL and a timing-controlled race
   (see `tests/Erp.IntegrationTests/Tenancy/GroupRoleRaceTests.cs` for the pattern).

Acceptance: build with 0 warnings; the full suite; the tenant-isolation suite; generator and dictionary drift clean; the
fresh Opus review in `docs/reviews/S1.11f2-review.md` with its high and medium findings fixed or ruled on.
