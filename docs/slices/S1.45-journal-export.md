# S1.45 Journal export: accounting events, account mapping, export files
Status: APPROVED by the standing ruling (CR-083): every recommendation (Q0 to Q6) is the ruling; CR-101 approved. Reserved numbers: CR-101, R-189 to R-190.
Class: C        Model: **Sonnet 5.5, medium effort**. No fresh review (no ledger; file generation from finalized results; reconciliation tests).
Requirements (all release 1.0): FR-HRM-PAY-30 (a `PayrollRunFinalized` event with totals by component, cost centre, department, project and company; export of journal files through the Accounting Export connector), **FR-XM-27** (an approved payroll posts one summarized entry per legal entity and cost allocation; employee detail stays in payroll;
a payslip is reversible before payment, afterwards correction by a later run), FR-XM-05 and -06, FR-HRM-LON-07 and EXP-06 (events from loans and expenses exported the same way), FR-HRM-CMP-07 (liability events), FR-ADM-INT-01 and -02 as they apply to connector setup.
Not built here: any Finance module, ledger table or chart of accounts (D-43: **never create ledger tables**); automatic posting; bank reconciliation. The export is a file or an API for a customer's accounting package.
Decisions: D-10, D-35, D-39, D-43, D-45. Spec to read (only these): `docs/specs/16-erp-baseline.md` section 6 FR-XM-27; `docs/specs/06a-…` PAY-30; `kernel.yaml` `itg.connectors`, outbox tables; S1.35b, S1.38 (finalize event), S1.40 (templates), S1.11a (events, jobs), S1.15 (template editor host).
Depends on: S1.38, S1.35b, S1.11a, S1.11c2.

## Goal
When a payroll is finalized, accountants receive one journal per legal entity and cost allocation in the format their accounting package imports, with the account mapping they control. Nothing is posted by us; the file is the hand-over, and reversals follow the same route.

## Build
1. **Accounting events (PAY-30).** Event `hrm.pay_run.finalized` from S1.38 consumed here; builds summarized lines by component, cost centre, department, project and company from results (employee detail excluded); loan, expense and liability events collected into the same journal set by date and company.
2. **Account mapping (Q1).** Table `hrm.account_mappings`: component or event kind plus cost-allocation dimensions to an account code string supplied by the customer; unmapped lines make the journal "incomplete" and block export, never guess.
3. **Export formats (Q2).** Format templates as data (CSV and Excel column layouts, a generic JSON), defined in the template editor; none for a specific package is invented; first customer's layout loaded as tenant data.
4. **Journals and files.** One journal per legal entity and run; balanced (debits equal credits, checked); export creates a file in the file store with checksum; re-export gives the same file; export history with who and when.
5. **Reversal (FR-XM-27).** A reversed or adjusted run produces a reversal journal (negated lines referencing the original) in the next export; originals never change.
6. **Screens.** Mapping editor, journal list and detail, export history, incomplete-journal worklist; English and Urdu.

## Acceptance
- A two-company run gives two balanced journals whose totals equal the run totals by component; an unmapped component blocks export and is listed.
- Re-export gives byte-identical files; a reversal run gives negated lines referencing the original.
- Loan disbursement, expense approval and liability events appear in the right journal. No ledger table exists (architecture test lists `hrm.account_mappings` and journal tables as export tables only).
- Tenant-isolation test for every endpoint; permission tests; FR ids in tests.

## Out of scope
See "Not built here".

## Questions (recommendations are rulings, CR-083)
- **Q0 Single part.** *Recommendation:* one part.
- **Q1 Mapping.** *Recommendation:* effective-dated mapping by component and dimensions; the customer's chart is just text.
- **Q2 Formats.** *Recommendation:* template data; neutral CSV and Excel shipped as examples only.
- **Q3 Granularity.** *Recommendation:* summarized by legal entity and cost allocation as FR-XM-27 says; employee-level detail never in the file.
- **Q4 Timing.** *Recommendation:* export on demand after finalize; no automatic send in 1.0.
- **Q5 Journal tables.** *Recommendation:* `hrm.journal_exports` and `hrm.journal_export_lines` hold export snapshots only (not a ledger); named so in the data dictionary.
- **Q6 Change request CR-101.** *Recommendation:* approve: tables `hrm.account_mappings`, `hrm.journal_exports`, `hrm.journal_export_lines`; consumer of `hrm.pay_run.finalized`; template type `journal_format`; permission `hrm.pay.journal.export`; expand-only.
