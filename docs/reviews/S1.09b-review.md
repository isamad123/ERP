## Summary for the product owner

The licensing work is sound in the places that matter most:
- A customer's licence is worked out on every request from the dates in the control plane, so it is right even if nothing has run.
- Modules and features that are not licensed answer exactly like pages that do not exist.
- A tampered, wrong-customer, older, expired or unknown-key entitlement is refused with its reason, and is never stored.
- Two administrators cannot take the last seat at the same moment.
- Locked and suspended customers can still sign in, read the licence page and export, and nothing is deleted.
- Every SQL statement uses parameters; no customer can see another customer's licence or usage (the isolation suite probes all three new endpoints).

I found **no high-severity defect**. There are **two medium issues**:

1. **People who close the browser without signing out keep a "concurrent user" seat for up to 12 hours.** The system already
   ends such a session after 30 minutes of inactivity, but the seat counter still counts it until the 12-hour absolute limit.
   A customer that bought, say, 50 concurrent users could have staff refused at sign-in even though far fewer people are working.
   I proved this with a test (finding 1).
2. **A small change to the list of licence keys in a later release could lock every customer at once.** If a stored, signed
   entitlement no longer passes the key list (for example a key is renamed), the system treats the customer as having no licence
   and locks it. Nothing checks this before a release goes live, and the hourly licence check would then record "locked" and
   announce it to the customer. **This needs your decision** on the safeguard (finding 2).

There are five low items (3 to 7). Two of them need a short decision from you: who may see limit warnings (4), and whether
the usage statement stays visible when locked (6).

My recommendation: fix 1 now (a few lines and the test already written), add the release-time check for 2, and fix 3, 5 and 7
with them because each is a few lines. Evidence is below.

## Findings, most severe first

### 1. MEDIUM: idle sessions keep holding concurrent-user seats until their absolute end (up to 12 hours)

- **Where:** `src/Platform/Erp.Kernel.Infrastructure/Entitlements/LimitCounters.cs:20-22` (`LimitSql.ConcurrentUsers` and
  `ConcurrentHeld`): `revoked_at is null and expires_at > now`. The session's `expires_at` is the absolute end
  (`iam.session.absolute_minutes`, default 720). A session not refreshed for `iam.session.idle_minutes` (default 30) is already
  ended at its next refresh (`AuthenticationService.cs:324`) and is not listed as live (`IdentityDb.LiveSessionsAsync`,
  `EnforceConcurrentLimitAsync`: `and last_seen_at > now - idle`), but the seat counter has no idle condition.
- **Scenario:** `users.concurrent = 50`. During the morning 50 people sign in; 20 of them close the browser at 10:00. At 11:00, 30
  people are working, yet the 31st person to sign in is refused 409 `errors.licence.limit_reached` until about 22:00. Ruling B2
  says "the distinct users with an open session"; an idle session cannot be used any more.
- **Proof:** `tests/Erp.IntegrationTests/Entitlements/EntitlementReviewFixTests.cs` (new): a user's session is moved two hours into
  the past, the limit is set to the live sessions plus one, and a new user activates. On the merged code: it fails with 409 `errors.licence.limit_reached.users.concurrent`, `used: 1, max: 1`: the only seat counted is the session idle for two hours. With the fix below applied locally (idle condition added to both statements) the same test passes; that change was reverted, nothing is fixed yet.
- **Fix:** add `and last_seen_at > $now - idle` to both statements, with the idle time read from the customer's
  `iam.session.idle_minutes` (the same rule as `LiveSessionsAsync`). Usage readings are not affected (they count named users).

### 2. MEDIUM: a stored entitlement that no longer passes the key catalogue locks the customer, and nothing catches it before go-live

- **Where:** `src/Platform/Erp.Kernel.Infrastructure/Entitlements/LicenceResolver.cs:35-46` (`TryParse`: "claims that no longer pass
  the key catalogue give no licence (fail closed: Locked)"), used by every request (`LicenceResolver.cs:74`) and by the licence job
  (`LicenceMaintenance.cs:84`). `migrate` never parses the stored entitlements.
- **Why it matters:** the stored claims were verified (signature and catalogue) when they were applied. Later releases change
  `entitlement-keys.json` and `EntitlementClaims.Parse` (the catalogue's own comment says keys are added with new modules). A
  key renamed or removed, a new required claim or a stricter limit rule makes the old, valid entitlements unreadable. On the
  first request after the deploy every affected customer is Locked; within the hour `kernel.licence_refresh` records
  `state.changed` to `locked` on both sides and the outbox event that S1.11 turns into "your licence is locked" e-mails.
- **Scenario:** release 1.1 renames `hrm.us` (or makes `support_tier` required). Every customer whose entitlement holds it is
  locked at once, with no warning and no operator alert.
- **Fix (needs your ruling):**
  - **A (recommended):** `migrate`, which runs at every release, parses every current and scheduled entitlement with the new
    catalogue and stops with a non-zero exit naming the customers and the reason, so the release is stopped before API hosts
    serve. Requests keep failing closed (tampering is still impossible because the control plane is trusted).
  - **B:** as A, and in addition a request whose stored claims cannot be read keeps the last state the licence job recorded
    instead of Locked, with an operator alert. More code; I do not think it is needed once A is in place.

### 3. LOW: a licence change can be announced twice when the licence job and an operator command run at the same moment

- **Where:** `LicenceMaintenance.cs:118-143` reads `meta.local_entitlement` version and state with no lock, then writes the copy and
  `RecordAsync`; `SetCopyStateAsync` has `where state is distinct from $1`, but the security event and outbox event are written
  regardless. `EntitlementApplier.cs:134-154` writes the copy and an `applied` event the same way.
- **Scenario:** the operator runs `licence refresh` (or `entitlement apply`) at minute 5, when `kernel.licence_refresh` runs
  (`jobs.json` `concurrency: 1` limits job runs only). Both read the old state; both record `kernel.licence.state_changed`, so
  administrators get two e-mails and the security log shows the change twice. The acceptance says "recorded once". The
  control-plane side is safe (rows locked `for update`).
- **Fix:** start both customer-side transactions with `select pg_advisory_xact_lock(hashtext('licence.copy'))` and read the copy
  after it.

### 4. LOW (needs a ruling): every signed-in user sees limit use and maximum through `/api/kernel/capabilities`

- **Where:** `LicenceService.cs:39-48` returns `warnings` (limit key, maximum, used, percent) to any holder of `iam.self.manage`.
- **Why:** the same figures on the licence page are limited to Tenant Admin and Auditor (`cfg.licence.read`, ruling Q16), and Q5
  puts warning banners in front of administrators. A business user can read how many seats or companies the customer has bought
  and uses, whenever a limit is above 90 percent.
- **Fix (recommended):** fill `warnings` only for callers holding `cfg.licence.read`; everyone else gets an empty list. Alternative:
  keep it as built (the banners of S1.12 would then decide who sees them).

### 5. LOW: a refused seat at activation or sign-in is recorded as the system user, without naming the person

- **Where:** `LimitGuard.cs:106` (`RecordRefusalAsync`) calls `ActorId(null)`, so a refusal on an anonymous step (activation, sign-in) is recorded
  with the system user and no holder; the warning path (`LimitGuard.cs:78`) passes the holder.
- **Fix:** pass the holder to `RecordRefusalAsync` and add `holder` to the details, so the security log says who was refused.

### 6. LOW (needs a ruling): the usage statement is refused when the licence is locked

- **Where:** `LicenceEndpoints.cs:32-34` has no `AllowedWhenLockedMetadata`; the test asserts the refusal
  (`EntitlementTests.cs:331`).
- **Why:** Q5 allows "the licence page" when locked, and S1.16 is "the licence and usage page". A locked customer's administrator
  cannot see the monthly figures they may need when talking to the provider. It is read-only data of their own.
- **Fix (recommended):** mark `GET /api/cfg/licence/usage` allowed when locked and change the test. Alternative: keep as built.

### 7. LOW: the usage statement chooses the month's limits by the database server's time zone

- **Where:** `UsageMeters.cs:123`: `created_at < ($2 + 1)::timestamptz` turns the customer's date into midnight in the
  PostgreSQL session time zone (normally UTC), not the customer's.
- **Scenario:** an entitlement applied on 1 June at 03:00 Karachi time (22:00 UTC on 31 May) is taken as applied in May. The statement can show a limit that was not
  yet in force for the customer. Billing is Later (ADM-PLT-07), so the effect today is a wrong percentage on one statement.
- **Fix:** pass the customer's month-end instant from the application (as the API already does with `licence.Today`).

## Checked and found correct

- **Tenant isolation:** the licence comes from the host-resolved customer only (`TenantResolution`, `TenantContext.Bind`); the
  usage statement queries `cp.usage_meters` by the bound tenant id; `LicenceProbe` covers the three endpoints (crossed host and
  token, forged token, headers and query naming another customer, unknown host, unchanged database, positive control).
- **Signed entitlements (spec 02 section 25):** one verifier for provisioning and apply: registered key with purpose `entitlement`,
  revoked key, validity window, signature, then the key catalogue (B3 parent, module and base-key rules); customer code; version
  higher than every stored one, checked again under `for update`; end date not passed (B4). Each refusal has a test.
- **States (B1, Q4 to Q6):** `LicenceStates.At` gives Active to E−30, Warning E−29 to E, Grace E+1 to E+14, Read-only E+15 to E+44,
  Locked from E+45; zero-day periods are skipped; negative or over-long periods are refused; perpetual stays Active. The day is
  taken in `org.time_zone`; unknown zones fall back to Asia/Karachi. Scheduled entitlements are in force from their start day
  without waiting for the job. Control-plane recording is idempotent under row locks.
- **Gate (Q9):** unlicensed or uninstalled modules answer 404 with no body, the same as a path with no endpoint; every `/api/hrm/*`
  endpoint carries an `EntitlementMetadata` of module `hrm` with a catalogue key (test). Removing a module keeps schema and data.
- **Locked and suspended (Q5, CR-040 item 4):** only sign-in steps, capabilities, the licence page and the audit export (a GET)
  answer; each still checks its permission.
- **Limits (Q7, B5):** the guard's advisory lock is taken before the count, and the count runs in READ COMMITTED after it, so it
  sees every committed seat; locks are always taken limit lock first, audit chain lock last (no lock-order cycle with the audit
  interceptor, which appends at `SavedChanges`). The company interceptor sees the tracked original values (`GetForUpdateAsync`), so
  re-activation and restore are caught; the generated user API cannot set `status`, so named users change only through the
  guarded services. A lowered limit refuses only new seats.
- **Migration and generator:** `V202611150306__controlplane__design_s1_09b.sql` is expand only (enum value, unique key replaced
  in a new file, new optional column with a partial unique key); no merged migration was edited.
- **Other rules:** no `DateTime.Now`/`UtcNow` in business code (the host cache uses machine time on purpose, CR-040 item 8); no
  edition name is tested in code (unit test `Spec16_SC3_…`); texts are localization keys in English and Urdu; no new package.
